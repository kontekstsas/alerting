# Мониторинг сайтов клиентов

Проверяет сайты каждые 2 часа через GitHub Actions и пишет в Telegram, когда что-то ломается.

## Зачем переписывали

24 августа 2026 у `forosaktiv.by` хостер приостановил аккаунт за неуплату. Старая версия
проверяла только код ответа — и молчала двое суток, потому что сервер отдавал:

```
GET /  ->  302  ->  /cgi-sys/suspendedpage.cgi  ->  200 OK
```

Для проверки по HTTP-коду это исправный сайт. Реклама в Google Ads и Яндекс.Директе
продолжала крутиться на заглушку хостера: клики шли, визиты в Метрике — нет.

Вторая проблема: workflow был в состоянии `disabled_inactivity`. GitHub отключает
расписание в репозиториях, где 60 дней нет коммитов. Последний запуск — 24.02.2026,
после чего мониторинг просто не существовал полгода, и об этом никто не узнал.

## Что проверяется

| Проверка | Что ловит |
|---|---|
| Код ответа | 4xx и 5xx |
| Адрес после редиректов | `suspendedpage.cgi`, `parked`, `expired` и подобное |
| Заголовок страницы | `Suspended page`, `Домен припаркован` |
| Текст страницы | «не обслуживается», «account suspended», «оплатите услугу» |
| Размер текста | пустая страница (< 500 символов) |
| Сравнение с обычным размером | текст усох втрое и больше |
| `must_contain` | пропала обязательная строка (телефон, название) |
| Мягкий 404 | несуществующий адрес отдаёт 200 и ту же страницу — сайт подменён на всех URL |
| Тип содержимого стилей | вместо CSS отдаётся HTML, сайт откроется без вёрстки |
| SSL | сертификат кончается меньше чем через 14 дней |

Заглушку Hostfly ловят сразу пять правил из этого списка — если хостер сменит
формулировку, сработают остальные.

## Как не спамит

- Сообщение отправляется при **смене** состояния: сломался или починился.
- Пока не починили — напоминание раз в 24 часа, не каждые 2 часа.
- Сетевые сбои (таймаут, 5xx) поднимают тревогу только со второго раза подряд:
  моргнувший сайт не будит никого. Заглушка и битые стили — тревога сразу,
  такое само не рассасывается.
- Раз в сутки в 09:00 по Минску приходит сводка, даже если всё хорошо.
  Это важно: молчащий бот и исправный бот теперь различимы.

Состояние живёт в `state.json` и коммитится обратно в репозиторий.
Файл `.keepalive` обновляется раз в неделю — свежие коммиты не дают GitHub
снова отключить расписание за неактивность.

## Настройка сайтов

```python
SITES = [
    'https://example.by/',                                   # обычная проверка
    {'url': 'https://slow.by/', 'timeout': 60},              # медленный сайт
    {'url': 'https://shop.by/', 'must_contain': '+375 44'},  # свой ключ проверки
    {'url': 'https://spa.by/', 'skip': ['catchall']},        # отключить проверку
    {'url': 'https://only.by/', 'network': 'by-only'},       # отвечает только из Беларуси
]
```

Доступные значения `skip`: `suspension`, `stub`, `catchall`, `assets`, `ssl`.

`network: 'by-only'` — для сайтов, которые не отвечают на запросы из-за рубежа.
С зарубежной машины обрыв связи для них считается ожидаемым и тревогу не поднимает,
но такие сайты отдельной строкой попадают в ежедневную сводку, чтобы про них не забыли.
Поведение зависит от переменной `MONITOR_LOCATION`: при значении `by` пометка не действует
и сайты проверяются как обычные.

Сейчас так помечены `flersalon.by`, `svaybel.by` и `mdcom.by` — они не отвечают
ни из одной зарубежной сети. **Нужно проверить из Минска**: если они там живы, пометка верна;
если мертвы — у клиентов проблема, а пометку надо снять.

## Где крутится

GitHub Actions, `.github/workflows/alerting.yml`, каждые 2 часа. Секреты
`TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` — в Settings → Secrets and variables → Actions.

Раннеры GitHub находятся за рубежом, поэтому в workflow задано `MONITOR_LOCATION=abroad`:
сайты с пометкой `network: 'by-only'` оттуда не проверяются и в тревоги не попадают.

**Если workflow оказался отключён** (состояние `disabled_inactivity`), включить его можно
только руками: Actions → Site Monitor → Enable workflow. Пуш сам по себе расписание не оживляет.
Проверить состояние:

```bash
curl -s https://api.github.com/repos/kontekstsas/alerting/actions/workflows | grep state
```

## Если переносить на свой сервер

Необязательный вариант, файлы лежат в `deploy/`. Для Ubuntu/Debian с root:

```bash
sudo bash deploy/install.sh
```

Установщик заведёт пользователя `sitemonitor`, соберёт venv в `/opt/site-monitor`,
положит секреты в `/etc/site-monitor/env` и включит systemd-таймер на каждые 30 минут.
`Persistent=true` добирает запуск, пропущенный из-за перезагрузки, а `OnFailure=`
пишет в Telegram, если упадёт сам мониторинг.

Если сервер в Беларуси — поставить `MONITOR_LOCATION=by` в env-файле, тогда пометка
`by-only` перестанет действовать и эти сайты будут проверяться как обычные.

При переезде workflow в Actions нужно выключить, иначе сообщения пойдут дважды.

## Проверить детектор

```bash
python monitoring_bot.py --selftest
```

Гоняет правила на сохранённой заглушке `tests/suspended_hostfly.html` и на нормальной
странице. Тот же тест выполняется в workflow перед каждой проверкой: если правила
перестали ловить заглушку, сборка падает — и это выяснится заранее, а не во время аварии.
